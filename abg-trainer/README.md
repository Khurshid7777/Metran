# Тренажёр КЩС (ABG Trainer)

Офлайн-тренажёр интерпретации кислотно-щелочного состояния и газов крови для всех возрастов — от недоношенных до взрослых. Три режима: калькулятор, тренажёр, экзамен. Бостонский подход по умолчанию, Стюарт (упрощённый Фенцль–Стори) в продвинутом режиме, расчёт коррекции с флагами противопоказаний. RU / UZ (латиница) / EN.

> Учебный инструмент. Не используется для принятия клинических решений.

## Команды

```bash
npm install
npm run dev            # разработка
npm test               # Vitest: эталонные кейсы, генератор (1000 кейсов × сценарий), ветви ядра, i18n
npm run test:coverage  # покрытие ядра (порог 90%)
npm run check:i18n     # нет текста в коде; ключи и плейсхолдеры RU/UZ/EN совпадают
npm run build          # офлайн-сборка в один файл dist/index.html
npm run test:e2e       # Playwright (после build): калькулятор, тренажёр, экзамен → PDF, a11y, офлайн
```

`dist/index.html` — единственный файл без внешних зависимостей: его можно скопировать на телефон или открыть с диска.

## Архитектура

```
src/
  core/          чистое ядро на TypeScript, без React
    units.ts         конвертация единиц, ввод с запятой/точкой
    validate.ts      шаг 1: диапазоны ввода, согласованность, общие флаги
    primary.ts       шаги 2–3: pH и первичное нарушение (нормы по возрасту и типу пробы)
    compensation.ts  шаг 4: бостонские формулы + копенгагенская проверка по SBE
    anionGap.ts      шаги 5–6: AG, поправка на альбумин, Δ/Δ
    osmolar.ts       шаг 7
    stewart.ts       шаг 8 (продвинутый режим)
    oxygenation.ts   шаг 9: PAO₂, A-a, P/F (Берлин), OI/OSI (PALICC-2, неонатальные пороги), S/F
    treatment.ts     бикарбонат, ЧД по pCO₂, направления для HFO, подсказки по причине
    interpret.ts     оркестратор: interpret(input, settings) → InterpretationResult
    generator.ts     генератор согласованных кейсов с самопроверкой (детерминирован по seed)
  content/       данные: norms.json, differentials.json, scenarios.json, cases/*.json, i18n/{ru,uz,en}.json
  modules/       интерфейс: calculator, trainer (+ questions.ts), exam, progress, settings
  storage/       localStorage с try/catch, записи попыток, KPI, экспорт CSV/JSON, код сертификата
  certificate/   PDF-сертификат (canvas → jsPDF, кириллица и узбекская латиница без встраивания шрифтов)
tests/
  core/          Vitest
  e2e/           Playwright
```

Контракт ядра: `interpret(input: AbgInput, settings: Settings): InterpretationResult` — массив шагов `{id, status, value, normalRange, verdict, explanationKey, flags, details}`, первичное и дополнительные нарушения, флаги, дифференциальный ряд, лечение и заключение в виде ключей i18n. Ядро не зависит от UI и может быть подключено к «Дневникам ОРИТ» и HFO-симулятору.

## Содержимое, которое утверждает клинический руководитель

- `src/content/norms.json` — все пороги и допуски (`approvedBy` пока пуст). Значения, не заданные в ТЗ явно, перечислены в `_assumed`: HCO₃⁻/BE для недоношенных, pH для «крайне тяжёлого» ацидоза при лактат-/кетоацидозе (7,1), порог лактат-ацидоза (4 ммоль/л), пределы ЧД по возрасту.
- `src/content/i18n/uz.json` — помечен `"reviewed": false` до сверки медицинских терминов.
- `src/content/cases/` — сейчас здесь **демонстрационные** кейсы (`"demo": true`), показывающие формат. Их нужно заменить реальными анонимизированными кейсами с эталоном эксперта и рецензентом. Кейс, на котором ядро расходится с эталоном, не попадает в выдачу, а показывается в «Настройки → Банк реальных кейсов» на рецензию.

## Генератор

`src/content/scenarios.json` — 23 сценария по трём уровням (одиночные, двойные, тройные нарушения, неонатальные, пуповинные, ОРДС, Стюарт). pH всегда выводится из уравнения Хендерсона–Хассельбаха, шум и округление — как у анализатора, затем кейс проходит через `interpret()`; несовпадение с задуманным → новая попытка (до 20). `npm test` прогоняет 1000 кейсов на сценарий и пишет долю отбракованных попыток в `logs/generator-report.json`.
